# Little Ears

一个 macOS 原生、完全离线的本地英语熏听播放器。当前交付 0.4 全局材质升级版，以真实播放和真实记录为基础，先体验，再继续迭代。

## 直接体验

打开 `build/Little Ears.app`，点击「选择音频文件夹」，选择你的故事或儿歌目录。

- 双击音频开始播放，或点击「播放全部」。
- 左侧目录树可切换目录；默认只显示该目录直属音频，勾选「包含子目录」可扩大范围。
- 音乐库中按 ⌘／Shift 多选歌曲，点击「加入播放列表」选择现有列表或新建；可以从不同目录分批加入。
- 左侧「播放列表」中拖拽歌曲排序，顺序自动保存。列表里的歌曲允许重复，右键可移除条目；菜单支持重命名和删除列表。
- 以后打开对应列表，点击「播放」即可；双击某条歌曲则从该条开始。
- 在「正在播放」查看队列，双击跳转，拖拽调整顺序；点击「保存队列」可另存为新列表，或明确确认后覆盖某个已有列表。
- 列表与队列互相独立；修改列表不会改变已生成的队列，临时调整队列也不自动修改列表。
- 底部可暂停、拖动进度、调节音量和切换顺序／队列循环／单曲循环。
- 「播放统计」显示真实时长、完整播放次数、7 天图表和音频时长排行。
- 设置提供跟随系统／深色／浅色主题和四种强调色。
- 关闭窗口保持播放；点击 Dock 重新打开。⌘Q 退出并保存。
- 重启恢复队列和位置，默认暂停，点击播放后继续。

快捷键：⌘O 添加目录，⌘P 播放／暂停，⌘← 上一首，⌘→ 下一首，⌘R 切换模式。

音频只被引用，不复制、不移动、不修改。扫描支持 MP3、M4A、WAV、AIFF、CAF、FLAC（大小写后缀均可），损坏或不可访问的文件可跳过。文件丢失后保留记录和统计，刷新目录可重新检查。来源行右键支持重新授权。

## 工程与构建

要求 macOS 14+、Xcode / Swift 5.10+。本次在 Xcode 26.6 / Apple Silicon 上构建和验证，尚未在 macOS 14 实机验证。

打开 `LittleEars.xcodeproj`，选择 LittleEars scheme 后 Run。也可打开 `Package.swift` 或运行：

```sh
swift test
scripts/build-app.sh release
open "build/Little Ears.app"
```

首次构建需下载锁定的 GRDB 7.0.0；应用运行不需要网络。构建脚本生成当前机器架构的本地签名 .app，未做 Developer ID 签名、公证或通用架构分发。

本地数据保存于 `~/Library/Application Support/LittleEars/library.sqlite`；主题偏好由 UserDefaults 保存。

## 首版范围

完成：目录授权与递归扫描、目录浏览／搜索／自然排序／多选播放、真实播放引擎、独立队列项、临时队列排序、播放列表创建／添加／排序／重命名／删除／队列另存、三种模式、恢复、系统媒体命令接入、SQLite 统计基础、主题与应用图标、真实音频频谱。

后续：LRC/TXT 歌词、封面和可折叠队列。M3：更完整统计详情、30 天趋势、文件重关联强化与长期稳定性验证。正在播放页以实时音频频谱为中心，取自实际播放 PCM，通过 Accelerate / vDSP FFT 计算；不使用随机柱形。

完整播放需要自然结束且覆盖至少 90% 内容。时长每 5 秒检查点，异常退出最多丢失约 5 秒；暂停、拖动跳跃、休眠不计入时长。详细行为与阶段验收见 [docs/DECISIONS.md](docs/DECISIONS.md)。

## 验证与限制

核心自动化测试包括内容覆盖去重、拖动末尾、跨午夜分配、真实 PCM 播放与暂停、数据库幂等保存、文件记录重关联与失效保留，以及真实导入 → 顺序播放 → 统计 → 重启恢复的集成路径。播放列表测试覆盖跨目录歌曲、独立条目、重复歌曲定位、排序与重启恢复、队列独立性、另存／覆盖、删除后保留原文件。

界面预览来自真实 SwiftUI 视图的离屏渲染，空库和零统计均为真实空状态，不注入演示数据。深浅主题、音乐库／播放列表／队列／统计／设置以及 900×600 紧凑窗口通过离屏视觉检查；新版完整鼠标与媒体键操作尚未逐项实机验收。音频输出、统计和恢复已通过独立测试验证；尚未进行连续一周和大规模音乐库压力测试。

FLAC 使用系统原生音频解码，按采样数读取准确时长，并补充读取 Vorbis 标题标签。运行不依赖 FFmpeg，也不会转换或改写音频。

FLAC 回归测试覆盖大小写后缀、子目录扫描、标题、准确时长、播放／暂停／拖动／自然结束和损坏标签。可选真实音乐库验证通过 `LITTLE_EARS_TEST_LIBRARY` 指定本次 jay 目录；验证在内存数据库中进行，不改写应用记录。该目录的 162 个 FLAC 和 2 个 MP3 均已扫描验证，FLAC 均读取了真实 PCM 片段。

0.4 的视觉系统与验证说明见 [docs/UI_DESIGN.md](docs/UI_DESIGN.md)。音乐库／播放列表为 32 pt 行高，队列为 52 pt，底部播放器为 68 pt。设置支持原生主题分段选择、四个强调色色块与频谱开关。

FFT 测试覆盖 44.1/48 kHz 音调定位、静音与衰减、右声道输入，以及播放引擎真实 tap 数据；与业务、缓存失效和播放进度隔离测试共 21 项通过。

开发预览命令（独立内存数据库，不写入你的播放记录）：

```sh
.build/debug/LittleEars --render-preview docs/previews
```

使用真实音乐库生成包含实际歌曲与频谱的预览：

```sh
.build/debug/LittleEars --render-preview build/ui-previews --preview-library /path/to/music
```

预览中的测试播放列表只存在于内存。暂停画面中的频谱取自当前位置文件 PCM 并由同一个 FFT 算法生成；实时播放 tap 另由自动化测试验证。

音乐库导航延迟的原因、修复与本机复测结果见 [docs/PERFORMANCE.md](docs/PERFORMANCE.md)。
