# Little Ears — macOS 原生英语熏听播放器开发方案

## 一、项目目标

你是一名精通 macOS 原生应用开发的高级工程师，同时具备优秀的产品设计和 UI/UX 能力。

请开发一款名为 **Little Ears** 的 macOS 原生本地音频播放器，主要用于儿童日常英语熏听，典型资源包括牛津树分级阅读音频、英文故事和儿歌。

产品定位：

**一款轻量、高性能、高颜值的 macOS 原生英语熏听播放器，以本地音频管理、灵活播放编排、长期播放统计和优雅的播放体验为核心。**

这不是在线音乐平台，也不是复杂的儿童学习管理系统。

产品必须满足以下原则：

1. **原生体验**：采用 Swift 和 SwiftUI 开发，遵循 macOS 交互习惯。
2. **轻量高性能**：低内存占用、快速启动、后台稳定运行。
3. **完全离线**：无需登录、无需服务器、无需网络连接。
4. **保护原始文件**：引用本地文件，不复制、不移动、不修改原始音频。
5. **数据可靠**：播放列表、播放统计、歌词关联和应用状态可持久化。
6. **视觉精致**：参考现代高品质 macOS 音乐应用，强调排版、留白、层次和微交互。
7. **避免过度设计**：优先满足真实使用场景，不引入不必要的功能和架构复杂度。

目标是交付一个真正可长期日常使用的应用，而不只是一个界面 Demo。

## 二、技术选型

采用以下技术栈：

| 模块 | 技术 |
|---|---|
| 开发语言 | Swift |
| UI 框架 | SwiftUI，必要时使用 AppKit |
| 音频播放 | AVFoundation |
| 音频频谱 | Accelerate / vDSP |
| 频谱绘制 | SwiftUI Canvas |
| 数据持久化 | SQLite + GRDB |
| 系统媒体控制 | MediaPlayer |
| 文件访问 | FileManager + Security-Scoped Bookmark |
| 用户配置 | UserDefaults |
| 最低系统版本 | macOS 14.0 |

禁止使用 Electron、WebView 或独立后端服务。

### 音频引擎设计

建议将播放器抽象为独立的 `PlaybackEngine`。

如果需要实现真实的实时频谱，可使用 `AVAudioEngine + AVAudioPlayerNode`，通过音频缓冲区进行 FFT 分析。

需要特别注意：

- 音频播放与 UI 渲染解耦。
- 不在音频实时回调中进行磁盘操作、数据库访问或复杂计算。
- 频谱分析使用后台处理。
- UI 更新频率控制在合理范围，避免持续高频刷新。
- 窗口隐藏时降低或暂停频谱绘制，但音频继续播放。
- 不为视觉效果牺牲播放稳定性。

优先实现可靠的基础播放链路，再逐步加入实时频谱。

## 三、整体产品结构

应用分为三个主要功能入口：

1. 音乐库（Library）
2. 播放列表（Playlists）
3. 播放统计（Statistics）

此外提供独立的沉浸式正在播放视图（Now Playing），并在常规页面保留全局播放控制。

推荐结构：

```text
Little Ears
│
├── 音乐库
│   ├── 已导入目录
│   ├── 目录树浏览
│   ├── 音频列表
│   ├── 音频搜索
│   └── 音频操作
│
├── 播放列表
│   ├── 创建播放列表
│   ├── 编辑播放列表
│   ├── 跨目录添加音频
│   ├── 自定义排序
│   └── 播放列表管理
│
├── 播放统计
│   ├── 今日统计
│   ├── 本周统计
│   ├── 本月统计
│   ├── 音频排行榜
│   └── 单曲播放详情
│
├── 正在播放
│   ├── 动态音频频谱
│   ├── 同步歌词
│   ├── 全文歌词
```

所有页面共享同一个播放器状态，切换页面不得中断播放。

## 四、本地音乐库

### 4.1 目录导入

支持选择一个或多个本地文件夹作为音乐库来源。

要求：

- 引用原始文件，不复制资源。
- 递归扫描子目录。
- 保留原始目录层级。
- 支持 MP3、M4A、WAV 等常见音频格式。
- 自动提取文件名、时长、格式等元数据。
- 以文件名作为默认标题，优先使用有效的音频元数据。
- 支持手动刷新音乐库。
- 支持在 Finder 中定位原文件。

目录授权需要通过 Security-Scoped Bookmark 持久化，保证重启应用后能够继续访问已授权目录。

### 4.2 文件变更处理

必须正确处理以下情况：

- 文件被删除。
- 文件被重命名。
- 文件被移动。
- 目录暂时无法访问。
- 外置磁盘断开。
- 重新连接原目录。

文件暂时不可用时，应保留音乐库记录、歌词关联和历史统计，不直接删除数据。

重新扫描时尽可能恢复关联，但不能仅凭相同文件名就错误合并不同音频。

### 4.3 音乐库交互

音乐库界面采用目录树 + 音频列表的方式。

支持：

- 单击目录查看内容。
- 双击音频开始播放。
- 选择目录直接顺序播放或循环播放。
- 多选音频。
- 右键加入播放列表。
- 根据标题搜索音频。
- 按名称、时长等基本属性排序。

目录播放默认只包含当前目录直接下属的音频，提供明确的「包含子目录」选项，避免用户无法判断实际播放范围。

## 五、播放列表与播放队列

这是产品核心功能之一。

### 5.1 三种对象

必须明确区分：

**目录（Folder）**

用于组织本地音频，反映磁盘结构。

**播放列表（Playlist）**

由用户自定义创建，保存指定音频及排列顺序。

**播放队列（Playback Queue）**

实际交给播放器执行的有序音频集合。

播放队列可以来自目录，也可以来自播放列表。

### 5.2 播放列表功能

支持：

- 创建、重命名、删除播放列表。
- 从任意目录添加音频。
- 一次选择多个音频加入列表。
- 跨目录混合编排。
- 拖拽调整播放顺序。
- 删除列表中的音频条目，但不删除原文件。
- 同一音频允许在一个列表中重复出现。
- 一键从头播放整个列表。
- 持久化播放顺序。

播放列表条目需要独立 ID，而不能简单使用音频 ID 作为唯一标识。

例如：

```text
本周熏听
├── 01 At School          Level 1
├── 02 The Toy's Party    Level 2
├── 03 Getting Up         Level 1
├── 04 At School          Level 1
└── 05 New Trainers       Level 2
```

### 5.3 播放队列规则

开始播放目录或播放列表时，生成对应的队列快照。

规则：

- 修改播放列表不应意外改变已经生成的队列。
- 当前播放队列支持查看和跳转。
- 当前音频切换时正确更新高亮状态。
- 重启应用后恢复上一次队列与播放位置。
- 恢复播放状态不等于自动开始发声，默认需要用户手动继续播放。
- 音频文件不可用时应提供提示，并允许跳过。

允许用户在当前队列里临时调整顺序，但不自动修改原播放列表；如需保存顺序，应有明确的保存操作。

## 六、播放模式

将播放来源与播放模式分开设计。

播放来源：

- 当前目录
- 自定义播放列表

播放模式：

| 模式 | 行为 |
|---|---|
| 顺序播放 | 队列播放完毕后停止 |
| 单曲循环 | 当前音频结束后重新播放当前音频 |
| 队列循环 | 队列最后一首结束后重新播放第一首 |

目录循环和播放列表循环统一复用队列循环逻辑。

播放器需要支持：

- 播放和暂停。
- 上一首和下一首。
- 拖动进度条。
- 音量调节。
- 切换循环模式。
- 显示当前播放时间与总时长。
- 键盘快捷键。
- macOS 媒体控制集成。

所有播放状态由统一的 `PlaybackManager` 管理，避免多个页面维护独立状态。

## 七、播放统计系统

这是产品的长期核心价值，必须在 V1 就建立可靠的数据基础。

### 7.1 统计指标

支持：

- 每首音频累计完整播放次数。
- 每首音频累计实际播放时长。
- 每日实际播放时长。
- 每周累计时长。
- 每月累计时长。
- 每日完整播放次数。
- 每首音频最近播放时间。
- 最近 7 天、30 天的播放趋势。
- 播放次数最多的音频排行。
- 播放时长最多的音频排行。

### 7.2 统计口径

必须明确以下规则。

**完整播放次数**

一次音频自然播放到末尾，记为完整播放一次。

单曲循环播放三遍，记录三次。

手动拖动至音频末尾不应直接产生虚假完成次数；对于这种情况要根据播放过程和结束原因判定。

**实际播放时长**

记录播放器实际处于播放状态的墙钟时间。

不包括：

- 暂停时间。
- 缓冲等待时间。
- 应用休眠时间。
- 拖动进度条造成的时间跳跃。

倍速播放若未来加入，仍应以实际墙钟时间作为熏听时长。

**部分播放**

即使没有自然播放结束，也应保留实际播放时长。

**跨天播放**

播放过程跨越午夜时，应将播放时长分配至对应自然日，而不是全部归属开始日期。

### 7.3 数据记录

建议采用播放会话记录与按日播放片段相结合的简单模型。

```text
PlaybackSession
├── id
├── trackId
├── playlistId?
├── startedAt
├── endedAt?
├── listenedSeconds
├── completed
└── endReason
```

为了正确统计跨天时长，以及异常退出后的数据，可以采用轻量的播放片段记录或可靠的增量检查点。

要求：

- 不因暂停、恢复而重复计数。
- 不因频繁拖动进度而虚增时长。
- 不因应用崩溃而丢失大量累计记录。
- 不因列表中重复引用同一音频而混淆统计对象。
- 不因历史音频文件丢失而删除统计数据。
- 统计按照用户本地时区汇总。

不要把统计实现成仅修改 `Track.playCount` 的简单计数器。

也不需要引入复杂事件总线、数据仓库或独立统计服务。

### 7.4 统计 UI

统计页面保持简洁，使用原生卡片和图表。

顶部展示：

- 今日熏听时长
- 本周熏听时长
- 本月熏听时长
- 累计完整播放次数

中间展示：

- 最近 7 天柱状图
- 最近 30 天趋势图

底部展示：

- 最常播放的音频
- 单曲累计时长与次数

支持点击单曲进入统计详情。

统计数字必须来自真实播放记录，不能使用演示数据或人为生成的数据。

## 八、歌词功能

支持两类歌词：

### 8.1 LRC 同步歌词

支持标准 LRC 时间戳，例如：

```text
[00:01.20]Here we are at school.
[00:04.60]We are having fun.
[00:08.30]Look at the children.
```

要求：

- 自动解析时间戳。
- 随当前播放时间定位对应歌词。
- 当前句子高亮。
- 其他句子降低对比度。
- 自动平滑滚动。
- 点击歌词跳转到对应时间。
- 暂停后保持当前高亮。
- 处理没有歌词、空行、重复时间戳等情况。

### 8.2 TXT 全文歌词

对于没有时间戳的英文故事文本，支持导入 TXT。

要求：

- 保留段落和换行。
- 支持滚动阅读。
- 不强制跟随播放进度。
- 不伪造同步时间点。

### 8.3 歌词匹配规则

优先扫描音频同目录中的同名文件。

例如：

```text
At School.mp3
At School.lrc
At School.txt
```

优先使用 LRC 作为同步歌词来源，TXT 作为全文阅读来源。

允许手动导入与替换。

歌词关联信息持久化，但不修改原始音频文件。

### 8.4 歌词展示模式

正在播放界面提供两个可切换模式：

- 同步歌词
- 全文阅读

有同步歌词时，优先展示同步模式。

无 LRC 但存在 TXT 时，自动展示全文模式。

## 九、UI/UX 视觉设计规范

这是产品的重要设计目标。

参考用户提供的现代深色音乐播放器界面，整体追求：

**原生、极简、精致、克制、有质感。**

不要使用传统 Windows 桌面工具风格。

也不要使用大量儿童卡通图案、花哨颜色或厚重拟物按钮。

### 9.1 页面布局

采用两种主要布局。

**标准管理布局**

适用于音乐库、播放列表和统计页面：

- 左侧导航栏。
- 中间主内容区。
- 底部固定播放控制区域。
- 可根据窗口尺寸调整布局。

**沉浸播放布局**

适用于 Now Playing：

- 左侧约 60%：播放可视化与歌词展示。
- 右侧约 40%：当前播放队列。
- 底部：上一首、播放暂停、下一首、进度和音量控制。

宽屏下保持舒适的留白和信息密度。

小窗口下允许切换或折叠右侧队列，不强行挤压主要内容。

### 9.2 主题系统

支持：

1. 跟随系统
2. 深色
3. 浅色

默认跟随系统。

提供四组强调色：

| 强调色 | 深色主题 | 浅色主题 |
|---|---|---|
| 冰川蓝（默认） | #80C8F2 | #347DB2 |
| 薄荷绿 | #78D9BE | #16846A |
| 薰衣草紫 | #B5A4F4 | #8063C8 |
| 暖珊瑚 | #F3A48F | #B75F4C |

深色主题建议：

```text
Background:    #15171B
Surface:       #22262C
Elevated:      #2B3037
Text Primary:  #F5F7FA
Text Secondary:#9FA8B3
Accent:        #80C8F2
```

浅色主题建议：

```text
Background:    #F5F6F8
Surface:       #FFFFFF
Elevated:      #EDEFF3
Text Primary:  #242A32
Text Secondary:#657182
Accent:        #347DB2
```

以上颜色作为视觉基准，并非要求所有元素硬编码这些值。

建立统一的语义化主题系统，包括：

- background
- surface
- surfaceElevated
- textPrimary
- textSecondary
- border
- accent
- accentSubtle

主题切换必须覆盖整个应用，包括频谱、歌词、队列、统计图表和按钮状态。

不要简单地把深色界面做颜色反转。

### 9.3 视觉细节

重点控制：

- 圆角与间距的一致性。
- 清晰的文字层级。
- 低对比度的边框。
- 轻微的背景渐变。
- 恰当的阴影。
- 选中态与悬停态。
- 精致的空状态与加载状态。
- 自然的页面切换动画。
- 系统字体的正确使用。
- Retina 屏幕下的锐利渲染。

优先采用 SF Symbols。

强调色只用于当前选中项目、播放状态、频谱、进度和重点操作，不要大面积铺满界面。

### 9.4 播放队列

参考提供的截图：

- 每条音频采用有层次的卡片或列表行。
- 当前播放项以强调色描边或柔和背景高亮。
- 支持音频封面；没有封面时使用统一、精致的占位图。
- 显示标题、所属目录或列表信息、音频时长。
- 支持拖拽排序。
- 支持双击跳转播放。
- 滚动条尽量符合 macOS 原生习惯。

### 9.5 播放控制

播放、暂停按钮应具有明确的视觉主次。

支持：

- 悬停反馈。
- 点击反馈。
- 播放状态过渡。
- 进度条拖动。
- 当前时间及总时长。
- 音量调整。
- 循环状态提示。

动画保持克制，避免过度弹跳、旋转等不必要的装饰。

## 十、音频频谱可视化

正在播放页面提供实时动态音频频谱。

视觉参考：

- 竖向频谱柱体。
- 默认冰川蓝色。
- 柱体具有柔和的高度变化。
- 适当的峰值保持与下降衰减。
- 深色模式可加入非常轻微的发光和反射。
- 浅色模式使用更清晰、克制的实心柱体。

### 技术要求

1. 从真实音频 PCM 数据计算频谱。
2. 使用 Accelerate / vDSP 完成 FFT。
3. 对频率区间进行适当分组。
4. 使用对数或其他合理映射改善视觉响应。
5. 对瞬时变化进行平滑处理。
6. 使用 SwiftUI Canvas 绘制。
7. 优先保证持续播放时的 CPU 与内存占用合理。

禁止用随机柱状高度冒充真实实时频谱。

频谱绘制与音频播放必须解耦。

关闭播放页面或最小化应用时，降低或暂停视觉刷新。

如果实时音频频谱对基础播放稳定性产生影响，应允许关闭频谱，并保证音频播放始终正常。

## 十一、系统集成

需要实现：

- macOS 原生窗口。
- 窗口关闭后继续后台播放。
- Dock 应用入口。
- 系统播放、暂停、上一首和下一首控制。
- 适当的键盘快捷键。
- 应用重启后的播放队列恢复。
- 应用设置持久化。

窗口关闭与退出应用要区分。

真正退出应用时，应妥善保存播放状态和统计记录。

菜单栏迷你播放器可作为后续增强功能，不作为 V1 阻塞项。

## 十四、开发阶段

按照以下顺序推进。

### M1：基础播放器

实现：

- 创建可运行的 macOS 原生工程。
- 建立主题系统和基础布局。
- 导入本地音频目录。
- 扫描并展示音频。
- 支持基本播放控制。
- 支持顺序、单曲循环、队列循环。
- 实现原始目录授权与持久化。
- 恢复上次播放位置。

验收目标：

**能够稳定地通过原始目录播放英文音频，关闭并重新打开应用后仍能继续使用。**

### M2：播放编排与视觉完善

实现：

- 自定义播放列表。
- 跨目录添加音频。
- 拖拽排序。
- 当前播放队列。
- 沉浸式播放界面。
- LRC / TXT 歌词导入与展示。
- 深色、浅色主题。
- 强调色配置。
- 实时音频频谱。

验收目标：

**可以方便地编排一个包含多个目录音频的熏听列表，并获得流畅、精致的播放体验。**

如果实时频谱开发影响阶段稳定性，应最后独立完成。

### M3：统计系统与稳定性

实现：

- 播放会话记录。
- 单曲累计次数。
- 实际播放时长。
- 每日、每周、每月汇总。
- 音频排行榜。
- 统计详情。
- 异常退出恢复。
- 文件变化和边界场景处理。
- 性能与稳定性优化。

验收目标：

**连续使用一周后，可以准确查询每天熏听时长、每首音频累计播放次数及听音时长。**

## 十五、质量要求

### 性能

- 应用启动迅速。
- 普通规模音乐库扫描不卡住 UI。
- 播放过程中不出现明显卡顿或音频中断。
- 歌词和频谱更新不影响音频播放。
- 不产生持续增长的内存占用。
- 后台运行时减少不必要的视觉计算。

### 稳定性

- 空音乐库正常展示。
- 不支持的文件格式可安全跳过。
- 损坏的音频文件不导致崩溃。
- 被移除的目录有明确提示。
- 播放列表包含失效音频时可继续处理。
- 数据库异常不能无提示地损坏原始数据。
- 异常退出后的统计与播放状态尽可能恢复。

### 代码质量

- 代码清晰，可维护。
- 主要业务规则有必要的单元测试。
- UI 与播放状态逻辑分离。
- Swift 并发使用安全，避免数据竞争。
- 数据库操作不阻塞主线程。
- 不存在明显的重复实现。
- 不留虚假功能、空按钮或无效交互。

## 十六、明确不做的功能

V1 暂不开发：

- 在线音乐服务。
- 用户注册与登录。
- 云端同步。
- iPhone / iPad 客户端。
- 音频下载与爬取。
- AI 自动转写。
- AI 英语学习评价。
- 多用户学习档案。
- 成就徽章与积分。
- 复杂的学习课程系统。
- 定时自动安排每天的内容。
- 高级音频编辑。
- 音乐均衡器。
- 插件系统。

睡眠定时、倍速播放、AB 复读、数据导出和完整菜单栏播放器作为 V1.1 候选功能。

## 十七、实施要求

请按照以下规则执行开发：

1. 首先检查当前项目目录，判断是新项目还是已有工程。
2. 如果是新项目，建立标准的 Swift / SwiftUI macOS 工程。
3. 先制定简洁的实施计划及阶段验收标准。

**最终验收标准：它应是一款可以每天打开给孩子播放英语音频、使用方便、统计可靠、界面精致的真正产品，而不是仅供演示的播放器。**
